# Mapper Component

## Overview

The mapper package provides the low-footprint, reflection-based object-mapping layer used across the framework. Its inspired by community mappers and focuses on struct-to-struct conversions backed by lightweight profiles. You declare the supported source/destination pairs up front, then call `Map` whenever you need to translate between those types. The package also understands slices, arrays, maps, and pointer variations without extra registrations.

## Registering a Mapping

Every conversion must be registered before the first call to `Map`. The library automatically registers both the pointer and value variants of the types you provide, so you only need to call one of the helpers:

```go
type UserEntity struct {
	ID        string `mapper:"id"`
	FirstName string
	lastName  string // private field
}

type UserDTO struct {
	ID        string
	FirstName string
}

func init() {
	if err := mapper.CreateMap[UserEntity, UserDTO](); err != nil {
		panic(err)
	}
}
```

If you need to implement a bespoke transformation (for example, combining fields or calling constructor logic), register a custom converter with `CreateCustomMap`:

```go
mapper.CreateCustomMap[UserEntity, UserDTO](func(src UserEntity) UserDTO {
	return UserDTO{
		ID:        src.ID,
		FirstName: src.FirstName + " " + src.lastName,
	}
})
```

Both helpers enforce that the provided types are structs (or pointers to structs) and return errors such as `ErrMapAlreadyExists` or `ErrUnsupportedMap` when the contract is violated.

## Mapping Data

Once a profile is registered, call `Map` with the source value and the desired destination type:

```go
userDTO, err := mapper.Map[UserDTO](entity)
```

The mapper automatically handles:

- Values and pointers (the registry keeps both variants).
- Slices, arrays, and maps (it loops element-by-element via `mapSlices`, `mapMaps`, and `mapPointers`).
- Field name matching (`fields`, `mapper` tags, camel-cased names, and exported methods are all considered).

If you pass a zero value (e.g., `nil` pointer, empty slice), `Map` returns the zero value for the destination type without error. When no mapping exists, you receive `ErrMapNotExist`.

## Field Resolution Rules

Profiles are generated by comparing source/destination metadata:

- The `mapper` struct tag (`field `mapper:"alias"`) is indexed alongside field names.
- CamelCase conversions are tried using `strcase.ToCamel` so `user_id` can map to `UserID`.
- Exported methods on the source struct (e.g., `ID() string`) are considered as virtual fields.

The mapper respects the order of registration. If a field is missing, it falls back to searching for a method with the expected name via `reflection_helper` before giving up.

## Configuration

Configure the package before registering mappings using `Configure`:

```go
mapper.Configure(&mapper.MapperConfig{MapUnexportedFields: true})
```

When `MapUnexportedFields` is `true`, private fields are accessed through the `reflection_helper` helpers. Otherwise, only exported fields and methods can participate in mapping.

The configuration persists for the lifetime of the process, so changing it after registrations may leave legacy profiles unaltered. Call `ClearMappings` to reset state when running tests or refreshing profiles dynamically.

## Registry Management

Use `ClearMappings` to drop every registered profile and return the mapper to its initial state (as would be the case on startup). This is especially useful for test suites that register ephemeral DTOs:

```go
mapper.ClearMappings()
```

The package relies on a simple registry keyed by source/destination `reflect.Type`. `CreateMap` implicitly stores both the pointer and non-pointer variants so you do not have to call it twice.

## Errors

The package exposes a handful of sentinel errors:

- `ErrUnsupportedMap` when the provided types are not struct-compatible.
- `ErrMapAlreadyExists` when you register the same pair twice.
- `ErrMapNotExist` when `Map` runs without a matching profile.
- `ErrNilFunction` when passing `nil` to `CreateCustomMap`.

Handle them just like any Go error so you can fall back gracefully in higher layers.

## When to Use the Mapper

- Translating between database entities, API DTOs, and domain models.
- Avoiding repetitive field assignments that follow a 1:1 convention.
- Reusing the same mapping configuration for arrays, slices, and nested structs.

## Summary

1. Configure once with `Configure` if you need unexported fields. Otherwise the defaults are safe for exported data.
2. Register every source/destination pair through `CreateMap` or `CreateCustomMap`.
3. Use `Map` to translate values; slices, arrays, maps, and pointers are all supported automatically.
4. Call `ClearMappings` in tests or in hot-reload flows where you need to rebuild mapping profiles.
